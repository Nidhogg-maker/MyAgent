# idea 思路与当前实现对照

本清单依据当前 MyAgent 源码核对。已实现表示存在真实执行代码；部分实现表示只覆盖本地受限范围；设计文档中的计划不算实现。模型准确率评测按用户要求暂缓，不作为当前核心落地的阻塞。

## 当前整体定位

已经跑通本地只读 Data Agent 核心链路：TheLook → dbt事实表 → 本地Metadata → 指标合同 → 检索/结构化上下文 → Task/Query → SQL编译 → DuckDB → Skill/Workflow → 持久会话 → 证据报告。

12个真实字段支撑的学习指标，6项可执行Skill，CLI连续提问与澄清，持久恢复。真实模型查询和14查询的完整比例分析均有记录。尚不是完整企业生产系统，也没有把金融支付业务接入本地数据。

## 逐项对照

| idea要求 | 状态 | 当前实现 | 仍缺少/边界 |
|---|---|---|---|
| Intent Recognition / Entity Extraction | 部分实现 | TaskInterpreter，真实模型严格JSON及有限规则 | 任意任务规划、复杂业务实体与广泛省略理解未完成 |
| Temporal Parsing | 部分实现 | UTC闭开窗口、相对日期、等时长比较、今天未结束拒绝 | 业务时区、多日历、同比节假日、指标成熟窗口 |
| Metric / Dimension Resolution | 已实现受限核心 | 12指标，别名，国家/性别值映射，合法维度校验 | 通用枚举注册服务和未知过滤值必澄清尚缺 |
| Ambiguity / Comparison Baseline | 部分实现 | 歧义口径澄清、回复续接、明确两窗口验证 | 自动比较基准选择策略；目前不猜默认基准 |
| Structured Task / Query | 已实现 | Pydantic Task/Query，禁止SQL/自报身份 | 通用逻辑计划、多事实复杂任务 |
| 高频知识/查询模板检索 | 部分实现 | 本地案例、别名、BM25式词法评分 | 大规模知识生命周期、历史案例自动沉淀 |
| Vector Search / RRF / Cross-Encoder | 未实现，按需 | 无此执行模块 | 当前不作为核心链路前提 |
| 指标缓存/物化视图 | 部分实现，非原设想完整缓存 | 有DWS表；会话内同版本查询回执复用 | 跨会话缓存、预聚合自动选择、失效管理；DWS不是当前查询自动加速层 |
| Structured RAG / Metadata Retrieval | 已实现受限核心 | 指标→事实/字段/质量/Owner/血缘，本地SQLite目录 | 独立Domain/Glossary服务、完整Dimension Registry、复杂元数据治理 |

| Knowledge Graph | 部分实现 | SQLite实体、Aspect及关系，表/字段依赖遍历 | 非完整业务实体图谱；不依赖专用图数据库 |
| Semantic Layer / DSL | 已实现 | commerce-v2唯一公式源，count/sum/distinct/条件计数/条件求和/ratio | 非MetricFlow等完整产品的功能覆盖 |

| 注入/权限/资源校验 | 部分实现 | SQL字面量、安全工具入口、本地签名身份/行过滤/小组抑制、只读worker | 企业SSO/ABAC、多租户、库侧行列权限与真实扫描成本估算 |
| 单Skill完整契约 | 部分实现 | SkillSpec/Registry/Executor，输入输出Schema、版本、依赖、超时和事件 | 前后置条件部分为描述，非通用可执行规则语言；工具依赖也不是动态授权引擎 |
| 复合Skill / Workflow | 已实现受限核心 | 固定查询/诊断流程，依赖环/深度校验，共享预算 | 任意动态DAG、并行调度、多版本发布和热加载 |
| 异常比较/分子分母/维度下钻 | 已实现 | 加法与比例分析；比例两维度14查询，加权贡献和总体对账 | 多指标相关联动、统计显著性、口径变更和事故关联验证 |
| 质量与因果边界 | 已实现检查与停止机制 | 查询现有质量/时间证据，反驳错误前提，缺证据停止归因 | 可信源水位、成熟状态历史、独立业务事件/因果识别 |

| Observability | 部分实现 | Skill/节点/查询事件、会话ID、查询审计、模型请求ID/Token用量 | OpenTelemetry/分布式trace、指标监控、告警与成本总账 |
| 连续提问/交互 | 已实现终端范围 | chat，澄清子会话，上轮任务上下文，分组追问，show/resume/cancel | 网页UI；规则模式仅支持有限明确追问，非任意会话记忆 |
| API服务/Docker/企业部署 | 未实现 | Python包、CLI、stdio MCP，本地运行 | HTTP API、Docker交付、身份集成、并发压测、生产运维 |

| 工程验证 | 已实现 | 最近完整回归112项；真实查询及持久工作流记录 | 模型准确率暂缓；工程测试不代表生产SLA |

## 代码与运行证据

- `tasks.py` TaskInterpreter：意图、时间、指标、歧义、上轮任务上下文。
- `retrieval.py` KnowledgeRetriever 与 `retrieval_context.py` resolve_context：词法候选、结构化解析和权威来源边界。
- `semantic.py` Query/SemanticRegistry/SQLCompiler：语义合同及SQL生成。
- `skills.py` SkillSpec/SkillRegistry/SkillExecutor：6项能力契约与执行。
- `diagnosis.py` DiagnosisEngine：比较、代数拆解、分组对账、质量与证据不足。
- `harness.py` build_agent：LangGraph固定分支；registered_skills路径用于新CLI运行时。
- `runtime.py` SessionStore/RuntimeTools/HarnessRuntime：状态、回执、预算、取消和只读恢复。
- `chat.py` chat_loop 与 `cli.py`：连续提问和会话管理命令。
- `service.py` AgentTools.execute：权限复核、执行隔离、实际查询取消/超时。
- `mcp_server.py`：原8工具接口，尚未暴露会话远程协议。
- `docs/runtime-workflow-demo.json`：14次查询、比较及三项分解、质量检查和事件。
- `docs/runtime-live-query.json`：真实模型经新Harness返回24.80%的男性订单完成占比。
- `docs/runtime-skills-tests.xml`：112项完整工程回归记录。

## 当前最值得补的核心缺口

1. **完整维度值解析**：未识别值不能直接查询为0；明确区分无数据、错误名称和未经授权。
2. **更完整异常证据**：接入口径版本变化、数据任务异常和快照状态成熟度检查，减少仅做数学分解。
3. **Skill与Runtime治理统一**：可执行前后置条件、错误分类、阶段预算/用量记录；保持有界Workflow。
4. **检索数据生命周期**：权威指标与知识引用版本一致、失效与冲突检查；无需先堆向量基础设施。

网页与远程部署可在上述核心稳定后推进；模型准确率、金融数据和企业身份目前均不应被误写为已完成。
