执行日期：2026-10-12。测试对象为当前本地合同、已发布 TheLook 数据与真实 E5/Cross-Encoder、真实 API Agent。未调参、未修改核心代码。

## 结论与可信范围

完成 60 条合同标注初版测试、13 项 raw 独立数值对账和 12 条真实模型自主 Agent 测试。测试集由开发助手依据合同编写，未经独立人工业务复核；所谓保留集只是暂定分层，不能宣称外部泛化成绩。

语义资产：21 份；快照 `aa7806511af56532e17a6f3c3cae585ef16b2293a126106b5d85f81a32873b69`。模型 `gpt-6.1-sol`，每题只运行一次。

统一服务会将精确匹配指标前置到 candidates；这里测的是资产 hits 排序，没有把前置后的指标候选成绩冒充原始检索成绩。“Top6内首个指标”仅筛去非指标资产，不追加精确匹配，因此也不等于实际 candidates 成绩。候选指标准确率尚未单独完整测量。Dense/RRF若把案例或通用规范排第一，在严格指标文档标签下属于Asset Top1失败，但不能直接推出Agent必然选错指标。

重排状态：{'skipped': 33, 'ready': 27}。错误从A4有效排名分母中剔除并必须计为运行失败；本报告不允许降级偷偷当成功。

E5 实际批量编码 60 个 Query，耗时 13.01 秒；之后使用同批真实向量评分。该优化只用于离线评测，不修改生产 Dense。评分秒数排除了批量编码，因此不能当线上端到端 P95；初轮不报告看似精确的线上检索 P95。Agent 下表耗时则包含真实模型、检索与执行。

## 理解与执行

规则理解/行为检查：28/60 (46.7%)。查询题逐字段比较 metric/start/end/group_by/filters；非查询题只检查没有生成可执行Task，这不是模型理解准确率，也没有严格验证澄清文字是否足够。

13个注册指标的结构化查询与 raw 独立对账：13/13 (100.0%)。订单状态来自原始 orders，金额来自原始 order_items 的decimal价格，订单日期使用 orders.created_at，跨事实比例独立用商品件数/订单数。全部同一UTC九月窗口；不能推导所有维度组合均已对账。

## 下一步与复现

先逐题业务复核与修正 Golden Label，再优先处理真实失败，不依据保留集反复调参后仍称其保留集。补全多轮、约束理由、诊断前提反证和非管理员权限；再扩展到全部60题真实模型及3次重复运行。若需要检索线上P95，必须增加真实单题冷/热链路计时，不能拿批量向量评分耗时代替。

现有60秒诊断超时问题没有在本轮放宽；本轮诊断测试集中是应澄清案例，未完成全诊断正确性验收。

复现：`python scripts/correctness-benchmark.py`；配置本机环境凭据后 `python scripts/correctness-benchmark.py --stage agent`；最后 `python scripts/report-correctness-benchmark.py`。凭据只能从本机DPAPI或环境加载，不能写入测试集。
