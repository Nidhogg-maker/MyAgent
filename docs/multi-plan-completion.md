# Multi Plan 与多事实语义升级完成记录

日期：2026-10-12。沿用用户新增的 AgentLoop 和 Agent 工具适配器，补齐候选方案管理与受控多事实查询。

## 已实现

1. 模型可提出 2–3 个候选方案，经 schema、授权、时间和语义编译检查后自行选择。
2. 候选按步骤执行，真实观察结果进入下一轮决策；支持有界重提，旧候选 ID 失效。
3. 候选、选择、步骤、观察、查询回执和模型 usage 写入已有会话/事件存储。
4. MultiFactQuery 显式指定指标、窗口、共同维度、过滤、并集/交集与注册派生公式。
5. 原事实分别聚合，再进行 NULL 安全关联；branch 不预截断，最后统一排序与 LIMIT。
6. 注册 items_per_order@1；每个组成指标独立授权，强制行过滤和小组抑制施加到每个分支。
7. 中文维度别名链接真实值；单分支缺失允许 null，所有分支都未知则澄清。
8. RuntimeTools 识别多事实请求，保持真实查询扣预算、回执复用、取消和重试约束。
9. CLI 新增 multi-query 与 agent --multi-plan；start-agent.ps1 加载已有本机加密模型配置。

## 仍然有边界

- 候选目前保持同一数值任务，改变组织步骤；不是自由任务DAG、并行候选试跑或任意假设搜索。
- 支持注册共同维度下的聚合结果关联，不支持任意事实明细、多对多分摊、SCD2时态关联或事件支付归属。
- 外层模型能选择 run_diagnosis，内部仍是固定异常 Workflow。
- 自主候选模式仍不支持任意步骤中断恢复；可查看记录、取消及澄清后开启新turn。
- 本次模型决策为模拟，未进行真实模型多方案验收或准确率评测。
- 文本摘要未自动证明，summary_verified=false、causal_claim=false；统计贡献仍不是因果证据。
- 新增工具在Agent进程内，MCP仍13项、原注册查询/分析Skill仍7项。

后续扩大Join能力，应先补明确实体键、桥表归属/权重、有效时间和业务对账，再扩展Planner；不能由模型自由猜测Join键替代口径。
